# Кластерное освещение и масштабируемые тени — план

> Решение владельца 2026-10-06. Статус: план, не начато. Пункт PLAN.md
> «Приложение B → B1 → R8». Начинаем после разреза `renderer.rs` на
> модуль `renderer/` (ветки `render/split-*`), чтобы новый код лёг в
> отдельные файлы (`renderer/lights.rs`, `renderer/clusters.rs`,
> `renderer/shadows.rs`), а не в 7-тысячный файл.

## 1. Зачем

Сейчас (master `fdeb3d9`) рендер держит:

- **8 источников** света фиксированным массивом `[GpuLight; MAX_LIGHTS]`
  в uniform `LightingUniform`; цикл в `shade_lit` перебирает все
  источники для каждого пикселя;
- **тени**: 2D-массив глубины на 4 слоя 1024² (направленные и прожекторы)
  + 2 кубические карты 512² (точечные); направленная тень — одна
  ортопроекция ±12 м (или подгонка под границы сцены), без каскадов;
- лишние источники и тени молча отбрасываются (счётчик
  `LightUploadStats`, один лог в `RenderLights::from_scene`).

Для сцен с десятками и сотнями источников (фонари, факелы, эффекты,
интерьеры) этого мало: и по числу, и по стоимости (каждый пиксель
платит за все источники), и по теням.

## 2. Почему кластеры, а не тайлы

Тайловый forward+/deferred режет экран на 2D-плитки и отбирает свет по
мин/макс глубине плитки — на краях объектов и в прозрачном это даёт
длинные списки. Кластерный (Olsson et al. 2012; Doom 2016, Unity HDRP,
Unreal forward) режет ещё и по глубине (экспоненциальные срезы), и
**одна сетка обслуживает все потребители**:

- deferred lighting pass (непрозрачное);
- forward-пасс прозрачного (у прозрачного нет одной глубины на пиксель —
  тайлы тут плохо работают, кластеры работают по глубине фрагмента);
- объёмный туман / рассеяние (сэмплы вдоль луча берут свет из кластера
  своей глубины).

WebGPU (WASM-таргет уже требует не-downlevel лимиты со storage-буферами,
см. `crates/wasm/src/lib.rs`) даёт compute-шейдеры — отбор делаем на GPU.

## 3. Цели и бюджеты

| Что | Сейчас | Цель |
|---|---|---|
| Источников в сцене (после CPU frustum-отбора) | 8 | 4096 (storage-буфер, растёт как instance-буфер) |
| Источников на кластер | — | до 128, переполнение считается, не роняет кадр |
| Тени: прожекторы/точечные | 4 слоя + 2 куба | 32+ одновременно из атласа по бюджету |
| Направленный свет | ±12 м, 1 карта | 4 каскада (CSM) со стабилизацией |
| Стоимость | O(пиксели × все источники) | O(пиксели × источники кластера) |

Конкретные числа производительности (1080p, 1000 точечных источников,
M1 / дискретная GPU / браузер) фиксируются замером в фазе 6, а не
заранее.

## 4. Фазы

Каждая фаза — отдельный draft PR в `render/…`, со своим гейтом.

### Фаза 1. Свет в storage-буфер

- `GpuLight` переезжает из `LightingUniform` в storage-буфер
  (`array<GpuLight>`), растущий как `grown_storage_buffer` у инстансов;
  в uniform остаются `light_count`, ambient, exposure, IBL.
- `MAX_LIGHTS = 8` как лимит загрузки уходит; лимит теней пока прежний.
- CPU frustum-отбор источников по сфере/конусу влияния до загрузки.
- **Гейт:** golden probe при ≤8 источниках пиксель в пиксель; тест
  «64 точечных источника — каждый освещает своё пятно»; `light_upload_stats`
  показывает 0 отброшенных до 4096.

### Фаза 2. Кластерная сетка и отбор на GPU

- Сетка 16×9×24 (плитки экрана × экспоненциальные срезы глубины
  near…far), размеры — константы с типами, не магические числа.
- Compute-пасс 1: AABB кластеров в view-space (пересчёт на resize и
  смене проекции).
- Compute-пасс 2: отбор источников (сфера точечного, конус прожектора —
  тест конус-AABB) → глобальный список индексов + сетка `(offset, count)`;
  атомарный счётчик переполнения.
- Направленные источники в кластеры не идут — отдельный короткий список.
- **Гейт:** CPU-референс отбора совпадает с GPU на наборе сцен
  (тест на равенство списков); переполнение отражается в статистике.

### Фаза 3. Шейдинг через кластеры

- Одна WGSL-функция (через shader-lang) «индекс кластера по
  `frag_coord` + view-depth → диапазон индексов»; её используют
  deferred lighting, forward прозрачного и туман.
- `shade_lit` перебирает только источники своего кластера.
- **Гейт:** при ≤8 источниках картинка совпадает с фазой 1 (допуск —
  только float-порядок суммирования, оговаривается в PR); прозрачное и
  туман получают тот же свет, что непрозрачное (тест).

### Фаза 4. Атлас теней с бюджетом

- Вместо 4 слоёв + 2 кубов — один атлас глубины (например 8192², на
  WebGPU — по `max_texture_dimension_2d`) с тайлами 2048…128.
- Каждый кадр источники с тенью получают тайл по важности: экранный
  размер области влияния, расстояние, интенсивность, флаг «герой».
  Дальние — меньше тайл или без тени (плавно, с гистерезисом от мерцания).
- Точечный источник = 6 тайлов (куб в атласе); прожектор = 1 тайл.
- Параметры теней (rect в атласе, VP-матрицы, bias) — в storage-буфере,
  индекс из `GpuLight.params.w`.
- Кэш статических теней: тайл перерисовывается, только если источник
  или кастеры в его объёме сдвинулись.
- **Гейт:** нынешние тесты теней (acne, occluder side, unmirrored texel,
  все техники) зелёные на атласе; новый тест «32 прожектора с тенями»;
  статистика заполнения атласа.

### Фаза 5. Каскадные тени для солнца

- 4 каскада CSM с практическим разбиением (log/linear), стабилизация
  (снап к текселю, сфера-обёртка против дрожания), смешивание на стыках.
- Заменяет ортопроекцию ±12 м и `shadow_fit_for_bounds` для больших
  сцен; подгонка под сцену остаётся как ограничение дальнего каскада.
- **Гейт:** тест «радиус сцены 500 м — тень у камеры чёткая, дальняя есть».

### Фаза 6. Отладка, метрики, бенч

- `ShadingDebug::ClusterHeat` — тепловая карта числа источников на
  кластер; режим показа тайлов атласа.
- Счётчики в статистике кадра: max/avg источников на кластер,
  переполнения, заполнение атласа, время compute-пассов (GPU timestamp,
  где есть).
- Бенч-сцена: 1000 точечных + 32 тени; замер и фиксация бюджетов в этом
  документе.

## 5. Не делаем сейчас

- Тайловый deferred как отдельный путь (кластеры его покрывают).
- Virtual shadow maps / ray-traced тени — возможное развитие атласа позже.
- Area lights и световые функции (IES) — после фазы 4.

## 6. Риски

- Лимиты WebGPU (`maxStorageBuffersPerShaderStage`, размер workgroup,
  `max_texture_dimension_2d`) — проверять через `adapter.limits()`,
  размеры сетки и атласа выбирать по ним.
- Порядок суммирования float меняет картинку на 1–2 LSB — golden probe
  обновлять только осознанно и с объяснением в PR.
- Мерцание теней при перераспределении тайлов — гистерезис бюджета.
