# Rust → WGSL: архитектура перехода

Статус на 2026-09-09: 11 stage-entry пишутся на Rust через `#[stage]`
и собираются в WGSL.base. Свободных идентификаторов в entry нет;
остаток (`EPS`/`PI` в хелперах, имена kernel-функций) — шаги ниже.
`naga` — backend деклараций + финальный валидатор, не источник API.

## 1. Текущее состояние (факт, сверено с кодом)

```rust
#[stage(vertex)]
fn vs_main(
    vertex_index: super::VertexIndex,
    ctx: Context<super::QuadContext>,
) -> CompositeVertexOutput {
    CompositeVertexOutput {
        clip_position: ctx.quad[vertex_index],
        uv: ctx.uvs[vertex_index],
    }
}
```

- **Сигнатуры — чистый Rust:** builtin-индексы — newtypes
  (`VertexIndex`/`InstanceIndex`, маппинг по имени типа как у glam);
  ресурсы — bundle `ctx: Context<Bundle>` (обёртка, не атрибут; голая
  структура `input: VertexInput` остаётся настоящим WGSL-параметром);
  location'ы — на полях `WgslInterface`-структур, entry берут struct-input
  (`input.uv`, не голый `uv`); located-возвраты — типом
  `-> Location<0, glam::Vec4>`.
- **Имя entry = имя Rust-функции** (`fn vs_main` → `fn vs_main`);
  `entry = "…"` остался опциональным оверрайдом, пользователей — ноль.
  Неймспейс замкнут: `{vs_main, fs_main}` на 11 entry.
- **Контракты:** bundle-структуры + `#[derive(ShaderContext)]`
  (`GLOBALS`); тесты `stage_globals_declared` (30 имён против сборок),
  `interface_field_order` (порядок полей литералов vs зеркал),
  `entry_points_match_pass_abi` (ABI попасно, не множеством).
  Renderer и `composite.rs` просят entry через `entry_point()`-аксессоры —
  литералов ноль.
- **Сборки** — обычные функции (`wgsl_source()`): типы — naga IR через
  derive (`naga_add_type`), ресурсы — таблицы `Resource` (WGSL-decl +
  `wgpu::BGL` из одного места), константы — const-expression композиты
  (`const quad`/`const uvs`, lowercase чтобы поле === глобалу).
  Известный workaround: writer naga 30 печатает load-only storage как
  голый `var<storage>` (баг `address_space_str`, в IR не решается) —
  постфикс с тестом-пином.
- **Честные границы:** proc-макрос не видит чужих item'ов — соответствие
  «поле → глобал» enforced тестами, не макросом; DSL — Rust-authored WGSL,
  не transpiler (функции не исполняются, семантика на naga/тестах);
  тела entry — DSL-only (шаг «валидный Rust» ниже).

## 2. Принятые решения (журнал)

- **Компромисс по naga (2026-09-08):** `Rust declarations → naga IR`,
  `Rust expressions/functions → собственный Shader IR → WGSL`,
  `naga → финальная валидация`. Не переводить тела на ручной naga IR
  насильно — источник всё равно Rust AST; функции — позже, если появится
  выгода. Отдельный writer и семантический слой (`wgsl.rs → Shader IR`,
  `wgsl_ir.rs`, `wgsl_writer.rs`) — следующим большим рефакторингом,
  когда DSL упрётся, а не наоборот.
- **Типизированный контекст (2026-09-09):** bundle-форма вместо
  per-param `#[wgsl(global)]` и свободных идентификаторов; плоская
  (`ctx.quad`), не вложенная (`ctx.quad.positions` — будущее, нужен
  типизированный резолвинг). Типы полей — настоящие (`CameraUniform`,
  `Vec<PerObjectGpu>`) или номинальные DSL-маркеры (`Texture2d`,
  `Sampler`), никогда не инстанцируются.
- **Single-source entry (2026-09-09):** имя → Rust-идентификатор;
  renderer — через аксессуары; ABI попасно в тестах.
- **Порядок миграции (инверсия приоритетов):** сначала дешёвые шаги с
  compile-time эффектом (контекст → типы → резолвинг), собственный
  IR-писатель — последним. Диагностика указывает на Rust-выражение;
  round-trip тесты сохраняются на каждом шаге.

Целевое (без изменений):

```text
Rust declarations ───────┐
                          ├─> Shader module ─> WGSL writer ─> naga
Rust functions ─> AST ───┘       (IR)
```

Требования к движению: Rust — главный источник истины (layout'ы,
интерфейсы, ресурсы, функции, entry); `format!` уходит из семантического
слоя; постобработка WGSL — только задокументированные workaround'ы;
типы/builtins — через symbols, не таблицы строк; до печати — место под
passes оптимизации/валидации.

## 3. Что дальше (по приоритету)

1. **«Валидный Rust» в телах:** выполнен первым срезом —
   `stage_field_uses_resolve` сверяет все не-свизловые `root.field` в
   entry против настоящих определений (`FIELD_NAMES` layout'ов,
   `WGSL_FIELDS` зеркал, `OPENPBR_SLOTS` для `mat`; 151 использование,
   неразрешённый корень — ошибка). Без моков и второго lowering'а:
   оракулы — реальные определения, текст — реальный выхлоп.
   Полная компиляция тел отклонена: orphan-правило запрещает
   `Index<VertexIndex>` для массивов/Vec, DSL-конструктор
   `Vec2::new(x)`-splat расходится с glam, а ~25 моков с угаданными
   сигнатурами дадут ложную уверенность вместо проверки.
2. **`ShaderType`/`TypeId` + enum builtin'ов** — выполнено:
   `shader_lang.rs` (`ShaderType`: скаляры/векторы/матрицы + `Quat`/
   `Vec2A`-алиасы; `ShaderBuiltin`: 36 вариантов с арностью,
   `lerp→mix` в одном месте вместо двух таблиц). Шесть разрозненных
   match-таблиц схлопнуты, `bool` исключён из примитивов (выхлоп тот же
   через старые фолбэки), неверная арность (`dot(x)`, пустой
   `length_sq`) — spanned-ошибка препрохода вместо наги/паники.
   Кернелы/нативные WGSL-имена идут мимо реестра verbatim, как раньше.
3. **Типизированный резолвинг:** выполнен тест-временным срезом —
   `stage_calls_resolve` (85 вызовов: builtins через общий реестр
   `ornis-shader-lang`, нативы, конструкторы, `fn`/`struct` из той же
   сборки; общий крейт-реестр понадобился, т.к. proc-macro крейты не
   экспортируют items) и `stage_resources_visible_at_stage` (28
   table-backed чтений против `visibility`; consts скипаются).
   Вложенные контексты разблокированы следующим шагом.
4. **Декларативный pass-объект** (бывший §3): один объект вместо
   пяти рассинхронизированных мест (таблица, header, BGL, decls,
   runtime binding). Выполнено полностью: `ShaderModule`-билдер
   (секции types → resources → consts → helpers → entries, порядок
   зашит в `emit`, call sites объявляют ЧТО); ручные `format!`-скелеты
   удалены из всех 9 сборок, 7 orphan-обёрток (`vertex_bindings`,
   `fragment_bindings` ×2, `bloom_header_head`, `composite_header_rest`,
   `fragment_head`, `vertex_quad_uv`) инлайнены; `bind_group_entries`
   строит runtime-биндинги из тех же таблиц (номера — из таблицы,
   call site маппит только имя → живой ресурс, 8 сайтов, дрейф доказан
   отсутствием пикселями). Полный `#[shader_pass]` — по необходимости,
   не ради синтаксиса.
5. **Разделить lowering и печать** — выполнено: `syn` строит IR, не
   `format!`. `ornis-shader-lang/src/{ir,writer}.rs` (`IrExpr` 17
   вариантов, `IrStmt` 5, `IrBinOp` 26, `IrCallee`
   Constructor/Builtin/Verbatim/Expr; writer владеет всеми WGSL-спеллингами
   включая квирки `/* names */`, `; `, `else {  }`), lowering в
   `macros/src/wgsl_lower.rs` (чистая функция `syn` → IR: calls
   классифицируются: конструкторы/`ShaderBuiltin`/вербатим; `powi`
   раскрывается в `Binary`-цепочку, свизлы — в `Field`, касты прозрачны),
   `wgsl.rs` ужался до фасада (~150 строк против ~1000: `WgslGen::expr`,
   типы, фрейминг `fn`/compute, те же публичные сигнатуры).
   Доказательства: все существующие exact-string тесты прошли БЕЗ правок
   (байт-идентичность), плюс структурные тесты lowering
   (`lerp` → `Builtin(Mix)`-узел, `powi(2)` → `Mul`-цепочка,
   `let = if` → 2 стейтмента) и writer-тесты в `shader-lang` (13/13) —
   трансляция впервые тестируема без строк. В траверсе ноль `format!`
   (остались только лексика литералов и фрейминг сигнатур).
6. **Расширять подмножество Rust** — закрыт как on-demand: все 11 entry
   транслируются, ни одно тело не требует недостающих конструкций
   (`match`/циклы-шаги/итераторы отсутствуют в шейдерах по факту, а не
   по запрету). Новые конструкции — когда появится тело, которому они
   нужны; IR-граница делает расширение аддитивным (узел + lowering +
   writer), а не правкой траверса.

## 4. Отклонённые альтернативы (чтобы не возвращаться)

- **Build-time compiler (build.rs с парсингом исходников)** — дублирует
  proc-макросы без инкрементальности cargo, хрупок (cfg/алиасы/
  re-export/expansion). Всё нужное достижимо иначе (п.1–3 выше). Цена —
  аддитивное время сборки + проект кэширования ради паритета с
  бесплатным. Разбор от 2026-09-09.
- **Const-generic биндинги (`Uniform<0, 0, T>`)** — group/binding живут
  в одном массиве на пасс; зашивка в тип превращает правку layout'а в
  правку сигнатур. Имена возвращаются строками в билдере.
- **`shader_module!` (module-level DSL)** — мощный cross-item анализ,
  но нестандартный синтаксис ради задач, решаемых функциями-сборками.
- **«Избавиться от макросов» как цель** — закон сохранения метаданных:
  она переезжает, а не исчезает. Цель — убрать их из семантического
  кода (выполнено).
- **Налог `.0`** — newtypes живут только в сигнатурной позиции, тела
  используют голый идентификатор; отдельное правило lowering'а не нужно.
- **Маркер-типы entry (`EntryPoint`-трейты)** — макросу нужна строка в
  момент экспансии, чужой `impl` он прочитать не может: строка осталась
  бы в `entry` anyway, тип — второе написание того же. Выбран один
  источник (имя функции → WGSL → аксессуар → пайплайн).
- **Суперседы (было → стало, 2026-09-09):** per-param `#[wgsl(global)]`
  → `Context<T>`; `entry = "…"` → имя функции; `QUAD`/`UVS` → lowercase;
  legacy `vs`/`fs` → `vs_main`/`fs_main`; мёртвый `hdr_fragment_vs_entry`
  удалён; `#[wgsl(builtin/location)]` в entry — ноль (newtypes +
  struct-inputs).
