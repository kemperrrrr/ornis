Повторная проверка прежней скалярной модели даёт те же величины при `θ=0.001`:

```text
Taylor-строка с rotation-log: 0.0009999995000
Текущая формула row_c:       0.0019999993333
Производная в нуле:          ≈2 при stamped Jangular=1

Для закрытия требуется согласованная тройка `C/J/H` и соответствующий тест, а не только удаление одного слагаемого с ослаблением тестовых порогов.

### A2: проблема разных масс — формула сохранена

Код: [`avbd.rs:1823–1838`](https://github.com/kemperrrrr/ornis/blob/931d085337d201a4183589f0ee6b78db3ad5ef53/crates/physics/src/avbd.rs#L1823-L1838).

Осталось:

```rust
let pen_d = (2.0 * m_dt2 / npts).min(PENALTY_MAX);
```

`m_dt2` по-прежнему рассчитан для текущего тела. Новый комментарий прямо говорит о разных K для A и B при неравных массах.

Скалярный пример из прошлого аудита после 10 итераций остаётся прежним:

```text
Массы:                   1 и 100 кг
Начальные скорости:      -1 и 0 м/с
Конечные скорости:       -0.600120 и -0.400180 м/с
Импульс:                 -1 → -40.618164 кг·м/с
Кинетическая энергия:    0.5 → 8.187291 Дж
```

**Это воспроизведение неизменившихся уравнений, не запуск Ornis.** Контрпример не потерял актуальности из-за изменения комментария.

Объяснение о влиянии замены контактной формулы на gear-сцену без контактов требует отдельного исследования. Само по себе оно не объясняет и не устраняет нарушение, показанное для пары разных масс. Предложенный в первом аудите black-box тест этой пары в коммит не добавлен.

### A4: новый `row_live` закрывает не весь дефект

Код функции: [`avbd.rs:594–609`](https://github.com/kemperrrrr/ornis/blob/931d085337d201a4183589f0ee6b78db3ad5ef53/crates/physics/src/avbd.rs#L594-L609). Вызов: строки 1856–1862.

```rust
fn row_live(c: f32, f: f32, pen: f32) -> bool {
    c.abs() >= C_EPS || f.abs() > pen * C_EPS
}
```

**Что улучшилось:** прежний пример `C=0, F=-10, K=100` теперь сохраняет контактную строку.

**Что осталось:**

1. В joints по-прежнему есть `if c.abs() < C_EPS { continue; }` до вычисления `K·C+λ`: например, [`avbd.rs:1941–1951`](https://github.com/kemperrrrr/ornis/blob/931d085337d201a4183589f0ee6b78db3ad5ef53/crates/physics/src/avbd.rs#L1941-L1951). Ограничение контактов не исправляет этот путь. Это прямо отмечено автором в документации `row_live`.
2. При допустимом `K=1e9` тот же контактный пример даёт `pen*C_EPS=100`. Сила 10 Н считается «пылью» и строка снова пропускается:

```text
row_live(0, -10, 100) = true
row_live(0, -10, 1e9) = false
```

Считать это автоматически безвредным нельзя. В скалярном нагруженном равновесии с `m/h²=3600`, инерционным gradient `+10` и реакцией `−10` полный шаг равен нулю. Если удалить и силу, и её Hessian, шаг становится `−10/3600 ≈ −0.002778 м`, то есть уже не «пыль» позиции.

Этот пример проверяет допустимый вход и алгебру helper-функции; достижимость такого penalty в конкретной игровой сцене в этой проверке не измерялась.

Для закрытия нужны проверки нагрузок и диапазона K, а не только happy path на малом penalty.

### A6: вырожденный friction ellipse не изменился

Код: [`avbd.rs:1686–1704`](https://github.com/kemperrrrr/ornis/blob/931d085337d201a4183589f0ee6b78db3ad5ef53/crates/physics/src/avbd.rs#L1686-L1704).

## Какие исправления подтверждаются

### A3: friction dual теперь сохраняет ограниченную силу

Код: [`avbd.rs:2662–2672`](https://github.com/kemperrrrr/ornis/blob/931d085337d201a4183589f0ee6b78db3ad5ef53/crates/physics/src/avbd.rs#L2662-L2672).

Теперь при `touching` оба тангенциальных `λ` записываются независимо от `s_ell`; только увеличение penalty остаётся под условием `s_ell <= 1`.

Прежний контрпример с сырым трением 14 и границей 5:

```text
λ_old = (-9,4,0), K = (100,100,100), C = (-0.01,0.1,0), μ = 0.5
До исправления:    λ_new = (-10,4,0)
После исправления: λ_new = (-10,5,0)
```

Именно замечание A3 этим устранено. Это не закрывает независимую проблему A6 или весь жизненный цикл контакта при размыкании.

### A5: восстановлена augmented-рекуррентность prismatic limit

Код: [`avbd.rs:2901–2908`](https://github.com/kemperrrrr/ornis/blob/931d085337d201a4183589f0ee6b78db3ad5ef53/crates/physics/src/avbd.rs#L2901-L2908).

```rust
let f_raw = j.pen_l[2] * c + j.lim_dual;
```

Теперь dual использует ту же сумму, что primal, до ограничения силы. Для `C=-0.01, K=1000, λ_old=-50` результат изменился с −10 на −60, как и требуется для прежнего контрпримера.

Комментарий о том, что присваивание `λ=F` якобы исключает старую λ из F, заменён корректным объяснением.

## Оценка нового теста и snapshot

Добавлен один тест: [`avbd_prismatic_limit_sustained_no_ratchet`, строки 638–683](https://github.com/kemperrrrr/ornis/blob/931d085337d201a4183589f0ee6b78db3ad5ef53/crates/physics/tests/avbd_engine.rs#L638-L683).

Плюс: длительность увеличена до 1500 шагов, что соответствует упомянутому в истории масштабу возникновения проблемы.

Ограничения:

- Assertions стоят **после** цикла, а не на каждом шаге. Промежуточный выброс с возвратом в допустимую область останется незамеченным.
- Проверяется конечная Y в диапазоне `[-5.6,-4.2]` и скорость меньше 1 м/с. Сам `lim_dual` и максимальная ошибка на траектории не проверяются.
- Sleep не отключён и пробуждение после длительного покоя не проверяется. Основной primal пропускает спящие тела, но `dual_update()` вызывается независимо от этого (`avbd.rs:1040–1046`). Поэтому тест не доказывает отсутствие скрытого роста multiplier у спящего ограничения и корректность последующего wake-up.
- Прямые тесты `row_live`, projected friction commit и dual recurrence не добавлены.

Не утверждаю, что текущий тест падает или что multiplier действительно разгоняется в этой конкретной сцене: локального исполнения Rust не было. Вывод — тест слабее утверждения «на всём горизонте нет ratchet/catapult».

Полезное усиление: frame-by-frame bounds/finite checks, максимум скорости и ошибки, контроль dual-состояния, прогон без sleep и отдельный цикл «покой → пробуждение → нагрузка».

Snapshot был обновлён. Декодирование hex подтверждает, что изменились только Y четырёх боксов: приблизительно −0.089, −0.162, +0.094 и −1.138 мм. Остальные записанные компоненты совпадают. Сам по себе re-baseline не доказывает корректность новых формул; это фиксация нового ожидаемого поведения.
