## 1. Новый дефект: angular unwrap применяется к линейной координате gear

**P2.** Код:

- [`joint_coordinate`, строки 2442–2451](https://github.com/kemperrrrr/ornis/blob/203319d4b1cc1c7e3ad9f083099f11099570677b/crates/physics/src/avbd.rs#L2442-L2451) возвращает угол для Revolute и линейное смещение для Prismatic.
- [`update_gear_mem`, строки 2492–2500](https://github.com/kemperrrrr/ornis/blob/203319d4b1cc1c7e3ad9f083099f11099570677b/crates/physics/src/avbd.rs#L2492-L2500) без проверки типа оборачивает разности обеих координат через `wrap_pi`.
- [`gear_sides`, строки 2511–2530](https://github.com/kemperrrrr/ornis/blob/203319d4b1cc1c7e3ad9f083099f11099570677b/crates/physics/src/avbd.rs#L2511-L2530) также применяет `wrap_pi` до определения `angular`.

```rust
let coord = match j.gear_mem {
    Some((prev_raw, prev_cont)) => prev_cont[k] + wrap_pi(raw - prev_raw[k]),
    None => raw,
};
```

Для угла это устраняет скачок через ±π. Для смещения в метрах операция modulo 2π неверна.

### Контрпример

Память линейной стороны `(prev_raw, prev_cont)=(0,0)`, новое смещение `raw=4 м`:

```text
Правильная линейная координата: 4
Текущий gear_sides:              -2.28318530718
Ошибка:                         -6.28318530718
```

Если затем `raw=4.01`, накопленная координата становится `−2.27318530718`: ошибка не исчезает на следующем малом шаге, а остаётся равной −2π.

Этот случай требует изменения линейной координаты более чем на π единиц за один интервал памяти: например, быстрой передачи или большого host-изменения позы. **Обычные малые prismatic-шаги этим контрпримером не опровергаются.** Но API допускает prismatic gear и не вводит такой метрический предел: проверка типа при создании разрешает и Revolute, и Prismatic (`3172–3175`).

Скалярная проверка одновременно подтверждает полезный angular-кейс:

```text
Угол 3.10 → -3.08: continuous = 3.20318530718, корректно.
Линейная координата 0 → 4: continuous = -2.28318530718, некорректно.
```

**Рекомендация:** делать unwrap только для `Revolute`; линейную координату `Prismatic` использовать без modulo. Исправить оба места — обновление памяти и live read. Закрепить mixed Revolute/Prismatic и Prismatic/Prismatic тестами, включая ±4 единицы смещения.

Это проверка исходников и численных выражений; полный сценарий gear в Rust здесь не запускался.

## 2. Что действительно исправлено

### A2: общий коэффициент speculative-контакта

Код: [`avbd.rs:1852–1860`](https://github.com/kemperrrrr/ornis/blob/203319d4b1cc1c7e3ad9f083099f11099570677b/crates/physics/src/avbd.rs#L1852-L1860).

```text
m_red = 1 / (inv_mass_A + inv_mass_B)
K = 2 · m_red / h² / number_of_points
```

Вместо текущего тела используются обе стороны пары. Для одного и того же контакта A и B теперь получают один K. Для static/dynamic случая нулевая inverse mass статики оставляет массу динамического тела.

Прежний скалярный пример: массы 1 и 100 кг, скорости −1 и 0 м/с, зазор 0.01, `h=1/60`, 10 итераций:

| Величина | Старая модель | Новая модель |
|---|---:|---:|
| Скорость A, м/с | −0.600120 | −0.339934 |
| Скорость B, м/с | −0.400180 | −0.006601 |
| Итоговый импульс при начальном −1 | −40.618164 | −1.000000 |
| Итоговая энергия при начальной 0.5 Дж | 8.187291 Дж | 0.059956 Дж |

**Это результаты скалярной модели, а не моего запуска Ornis.** Исправленный black-box тест [`avbd_speculative_pair_does_not_create_momentum`, строки 740–770](https://github.com/kemperrrrr/ornis/blob/203319d4b1cc1c7e3ad9f083099f11099570677b/crates/physics/tests/avbd_engine.rs#L740-L770) проверяет именно прежний контрпример: mixed masses, нулевая гравитация, импульс и энергию. Это адресная проверка, а не ослабление старого settle-порога.

Остаточные проблемы вращательных контактов A1 этим не закрываются: симметрия K исправлена независимо от C/J.

### A6: вырожденный эллипс трения

Fn=-10, μ=(0.5,0), raw tangent=(10,0)  → (5,0)

Добавлен поведенческий тест [`avbd_degenerate_friction_ellipse_keeps_live_axis`, строки 700–737](https://github.com/kemperrrrr/ornis/blob/203319d4b1cc1c7e3ad9f083099f11099570677b/crates/physics/tests/avbd_engine.rs#L700-L737): один бокс должен тормозить вдоль оси с трением, другой — свободно двигаться вдоль оси с нулевым μ. Он направлен на заявленную ошибку. В дополнение полезны прямые unit-тесты проекции для обоих порядков осей.

## 3. A4: закрыт контактный пример с большим K, joints не исправлены

Код: [`row_live`, строки 594–612](https://github.com/kemperrrrr/ornis/blob/203319d4b1cc1c7e3ad9f083099f11099570677b/crates/physics/src/avbd.rs#L594-L612), вызов на строке 1883.

В условие добавлен масштаб `m/h²`:

```rust
c.abs() >= C_EPS || f.abs() > pen * C_EPS || f.abs() > mass * C_EPS
```

Для ранее предложенного примера `C=0, F=-10, K=1e9, m/h²=3600` функция теперь возвращает **true**: 10 Н больше `3600·1e-7=0.00036 Н`. Прежний конкретный дефект этого helper закрыт по коду и модели.

Но joints остаются на старом guard. Например, [`avbd.rs:1965–1975`](https://github.com/kemperrrrr/ornis/blob/203319d4b1cc1c7e3ad9f083099f11099570677b/crates/physics/src/avbd.rs#L1965-L1975) для Ball/Revolute/Fixed пропускает строку при малом C **до** вычисления `K·C+λ`. Prismatic perp-строки имеют то же условие (`1982–1992`).

Поэтому весь A4 остаётся частично открытым. Не утверждаю, что новый эвристический gate является доказанно эквивалентным полной Newton/VBD-сборке на всех масштабах и геометриях; проверен прежний конкретный контрпример.

## 4. A5: формулу AVBD снова заменили proportional-правилом

Primal: [`avbd.rs:2391`](https://github.com/kemperrrrr/ornis/blob/203319d4b1cc1c7e3ad9f083099f11099570677b/crates/physics/src/avbd.rs#L2384-L2405).

Dual: [`avbd.rs:2973–3002`](https://github.com/kemperrrrr/ornis/blob/203319d4b1cc1c7e3ad9f083099f11099570677b/crates/physics/src/avbd.rs#L2973-L3002).

```text
Primal: F = clamp(K·C + lim_dual)
Dual:   lim_dual = clamp(K·C)
```

Это отменяет исправление `931d085`. Прежний численный пример снова расходится:

```text
C=-0.01, K=1000, λ_old=-50
Augmented update: -60
Текущий dual:      -10
```

**Позитивное изменение документации:** теперь комментарий прямо называет правило не textbook augmented-Lagrangian. Это уже не ошибочная претензия на точный порт.

Можно осознанно выбрать такую penalty/servo-строку как часть гибридного решателя. Но это смена математического контракта, а не устранение A5 как замечания о соответствии AVBD. В установившемся скалярном режиме сила около `2K·C`, поэтому удержание нагрузки требует ненулевой ошибки.

Комментарий сообщает о катапультировании при накопительной версии. Я не воспроизводил этот игровой прогон и не предлагаю вслепую возвращать нестабильный вариант. Однако ограничение penalty само по себе не доказывает неизбежность windup корректного augmented-решателя: ненулевая λ как раз позволяет держать нагрузку при нулевом C. Исходную нестабильность надо разбирать вместе с primal-guard, slop, warm start и sleep, а не объявлять их влияние устранённым одной заменой dual.

### Что стало лучше в тесте prismatic

[`avbd_prismatic_limit_sustained_no_ratchet`, строки 639–697](https://github.com/kemperrrrr/ornis/blob/203319d4b1cc1c7e3ad9f083099f11099570677b/crates/physics/tests/avbd_engine.rs#L639-L697) теперь проверяет скорость на каждом шаге после первых 200 шагов: `<10 м/с`. Предыдущее замечание о возможности пропустить промежуточный выброс после этого момента частично учтено.

Ограничения остаются: первые 200 шагов не контролируются этим guard, положение проверяется только в конце, sleep не отключён, нет wake-up цикла и прямого контроля dual-состояния. Главное — тест теперь относится к **proportional-варианту**, а не подтверждает устойчивость восстановленного AVBD dual.
