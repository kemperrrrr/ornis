## What drove the increase (45.77% → 83.32%)

1. **editor-backend crate extraction** — `remote.rs` 97.09%, `ipc.rs` 92.26%.
   (23 new tests: HTTP server + IPC round-trips.)
2. **crates/audio** — raised 0% → 67% (later 83% after the panning fix),
   19 unit tests. Found and fixed two real bugs:
   - `symphonia` was missing the `pcm` feature → PCM WAV decode returned
     `Unsupported`. (feature flag added.)
   - `pan_sample` azimuth contract was inconsistent across backends
     (see `audio-panning-bug-2026-08-25.md`). Native now uses equal-gain
     linear pan; wasm PannerNode now applies elevation + linear distance
     model (rolloff / reference_distance).
3. **crates/macros** — unit-tested private internals (`turbofish_type`,
   `check_send_sync_bounds`, `compute_threshold`, `compute_lane_target`),
   3 `Pack` functional smoke tests, 3 trybuild compile-fail fixtures for
   `Pack` error paths. `pipeline_config` 66.85% → 76.16%; `wgsl.rs` control
   flow extracted into `mod wgsl_flow` (wmc dropped below the bca limit).

## Known gaps (not regressions — by design)

- `crates/audio/src/engine.rs` (103 lines, 0%): `AudioEngine` owns a `cpal`
  audio stream; cannot run without a real audio device in CI. Covered
  indirectly via the mixer unit tests (`pan_sample`, `distance_attenuation`,
  `mix`) and the decoder tests — the engine is a thin orchestrator.
- `crates/macros/src/{kernel,gpu_pipeline,for_each_entity}` error paths:
  the `compile_error!` branches are only exercised by trybuild on `Pack`;
  the other macros' error paths are not yet under compile-fail tests.
- `ornis-materialx/graph.rs` (~74%): graph traversal helpers partly
  uncovered — candidate for next coverage pass.
