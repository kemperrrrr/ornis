## Что внедрено

### 1. `cargo xtask quality` — единый гейт (xtask/src/quality.rs)

Архитектура стадий: стадия не прерывает прогон, в конце — сводная
таблица PASS/FAIL/SKIP/INFO, exit code 1 по худшей стадии.
Отсутствующий инструмент → SKIP с подсказкой `cargo install ... --locked`.

- **default (уровень 1):** `fmt --all -- --check` →
  `clippy --workspace --all-targets -- -D warnings` → `test --workspace` →
  `audit` → `deny check` → `outdated --workspace` (informational,
  ненулевой exit при устаревших зависимостях не валит гейт).
- **`--full` (уровень 2):** + `llvm-cov --workspace --html --output-dir
  target/llvm-cov` (html-отчёт + сводка в консоль) и
  `bench --workspace --no-run` (criterion компилируется).
- **`--bench`:** + полный прогон criterion (долгая стадия, отдельно).
- **`cargo xtask fuzz <target>`** и **`cargo xtask mutants`** — отдельные
  сабкоманды, не входят в default.

Проверено: default и `--full` — зелёные, exit 0 (162/162 тестов,
coverage 45.77%, html в `target/llvm-cov/html/`).

### 2. proptest (уровень 2, тесты)

`crates/core/tests/property_tests.rs` — **15 свойств**, 64 случая на
свойство (ограничено, чтобы не раздувать `cargo test`; весь файл
отрабатывает за ~0.1 с):

- **ComponentStore (sparse set):** insert→get; повторный insert
  перезаписывает без роста len; remove возвращает значение и очищает слот;
  remove отсутствующего — None; протухший handle (другая generation) не
  читает чужой компонент; **model-based** против HashMap — случайная смесь
  insert/remove: swap-remove ничего не теряет, iter покрывает ровно живые
  entity.
- **EntityAllocator:** свежие аллокации живы и уникальны; recycling слота
  повышает generation, старый handle мёртв; model-based alloc/dealloc.
- **PageTable:** set→get на разреженных индексах до 100k (много страниц);
  нетронутая страница → None, нетронутый слот тронутой страницы →
  Some(default).
- **AABB/Ray:** from_points ⊇ все точки; expand сохраняет содержимое;
  overlaps коммутативен; point_at линеен.

**Найдено proptest'ом и исправлено** (реальные баги, а не тестовые):
1. `ComponentStore::insert` существующего id не обновлял generation
   записи — свежий handle не мог прочитать собственный компонент.
2. `ComponentStore::remove` игнорировал generation — протухший handle
   мог удалить чужой компонент.
Оба пути приведены к семантике get/contains (проверка generation).

`fuzz/` — независимый cargo-fuzz крейт (пустой `[workspace]` отсоединяет
его от корня; в `members` корневого Cargo.toml **не добавлять**).

100 прогонов без крашей; seed corpus закоммичен в `fuzz/corpus/`.

Три job на push/PR в `master`, кэширование — Swatinem/rust-cache@v2:

- **quality** (ubuntu-latest): apt `libasound2-dev libudev-dev

это локальные/ночные стадии уровня 2.
