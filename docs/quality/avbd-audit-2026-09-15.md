# Проверка реализации AVBD — 2026-09-15

## Краткий вывод

**Да: в Ornis реализуется именно AVBD, а не переименованный sequential-impulse или обычный penalty-решатель.** Есть характерное вычислительное ядро: локальная 6×6 система на тело, primal-sweep по положениям, отдельный dual-update, сохраняемые множители Лагранжа и изменяемые штрафные коэффициенты.

**Но текущую реализацию нельзя считать корректным воспроизведением эталона.** Найдены конкретные расхождения в математике контактов и обновлении dual-состояния, а также проблема в дополнительном speculative-contact демпфере. Некоторые комментарии называют изменённые правила «official» или «verbatim», хотя они отличаются от первоисточника.

Это аудит конкретного снимка, не оценка намерений разработчика и не утверждение, что все сцены неработоспособны. Производственный код не изменялся.

## 1. Почему это действительно AVBD

Определяющий признак — решение по **телам**, а не только по отдельным контактным импульсам: построить локальную систему для изменения позы тела, пройти тела, затем обновить силы ограничений и штрафные коэффициенты. Для hard constraints сила содержит обе части, `F = K·C + λ`; после primal-прохода новый `λ` получается из этой силы с нужной проекцией на допустимые границы. [8](https://graphics.cs.utah.edu/research/projects/avbd/Augmented_VBD-SIGGRAPH25.pdf)

| Элемент | Где в Ornis | Оценка |
|---|---|---|
| Инерционная цель `y = x₀ + h·v₀ + h²·g` | `avbd.rs:984–987` | Есть |
| Масса и вращательная инерция в локальной системе | `avbd.rs:1711–1734` | Есть |
| Вклады `JᵀKJ`, `JᵀF`, линейно-угловые блоки | `avbd.rs:1680–1707` | Есть; некоторые передаваемые `C/F/K` ошибочны, см. ниже |
| Решение 6×6 через LDL и изменение позы | `avbd.rs:233–275`, `2352–2356` | Есть |
| Primal по телам, затем отдельный dual | `avbd.rs:1020–1029`, `2556–2901` | Есть |
| Сохраняемые `λ` и penalty по строкам | `avbd.rs:598–609`, `663–720` | Есть |
| Warm start с затуханием | `avbd.rs:989–1009` | Есть для основных массивов |
| Геометрическая жёсткость, диагональная SPD-аппроксимация для ball-anchor | `avbd.rs:288–310`, `2089–2111` | Есть |
| Восстановление скоростей из изменения позы | `avbd.rs:1030–1047` | Есть |

Эта структура соответствует AVBD и авторскому демо. Отсутствие GPU само по себе не означает подмену алгоритма: авторское доступное демо также использует последовательный проход по телам. [3](https://github.com/savant117/avbd-demo3d)

Это не только throwaway-spike: `AvbdEngine` реализует `PhysicsEngine`, а `SolverKind::Avbd` создаёт его через публичный оркестратор (`crates/physics/src/lib.rs:56–141`). Однако стандартный `PhysicsRuntime::new` выбирает `SolverKind::Builtin` (`src/engine_runtime.rs:40–47`); само наличие работающего редактора ещё не подтверждает работу AVBD в нём.

## 2. Найденные проблемы

**Приоритеты:** P1 — исправить до заявления о корректности математического ядра; P2 — конкретное расхождение/дефект отдельного поведения, требующий исправления и регрессионного теста. Приоритет не означает, что ошибка уже воспроизведена во всех сценах Ornis.

### A1 · P1 — Вращение дважды входит в контактную невязку

**Код:** `avbd.rs:1636–1651`; вызывается и primal-, и dual-проходами.

В авторском `manifold.cpp:74–91` используются отдельно перемещение **центра** и вращательный член:

```text
C = (1−α) C₀ + u·(ΔpA−ΔpB)
                  + (rA×u)·ΔθA − (rB×u)·ΔθB
```

Это реализация контактной Taylor-аппроксимации. [3](https://github.com/savant117/avbd-demo3d)

В Ornis вместо `ΔpA` уже берётся изменение положения **вращающегося якоря**, после чего ещё раз добавляется вращательный член:

```rust
let d_a = (a.position + ra_w) - (self.pos0[pair.a] + ra_w0)
    + u * (ra_w.cross(u).dot(quat_diff_vec(...)));
```

Таким образом, в первом порядке вращение учтено дважды. При этом `stamp_row` использует обычный `Jangular = r×u` (`1689–1699`), без такого удвоения: невязка и собираемая система рассогласованы.

**Численный контрпример:** центр неподвижен, якорь `(1,0,0)`, строка вдоль Y, поворот вокруг Z на `θ=0.001`:

| Вариант | Значение `C`, м |
|---|---:|
| Эталон с его quaternion-chord | `0.0009999994583` |
| Та же Taylor-строка с rotation-log Ornis | `0.0009999995000` |
| Текущий `row_c` Ornis | `0.0019999993333` |

Производная Ornis в нуле ≈2, а передаваемый в систему угловой якобиан равен 1. Это не эффект замены chord на exponential/log: разность этих двух способов на таком угле мала, тогда как лишний член имеет первый порядок.

**Проверка на скомпилированном эталоне, f32, отрицательный угол для активного push-only normal:**

```text
rotation: reference C=-0.000999999582;
          Ornis scalar formula=-0.0019999994; ratio=2.00000024
```

**Последствие:** неверная связь поступательного и вращательного движения в контакте; риск ложного slip и неправильных моментов. Полная траектория Ornis в этом аудите не запускалась.

**Исправление:** выбрать согласованную формулировку — Taylor по перемещению центра и вращению либо нелинейное изменение якоря с соответствующими производными. Не складывать оба варианта. Добавить тест якобиана и тест качения без проскальзывания.

### A2 · P1 — Speculative-демпфер задаёт разные жёсткости сторонам одной пары

**Код:** `avbd.rs:1712`, `1767–1799`, особенно `1795`.

Для разделённой, но сближающейся пары вычисляется:

```text
pen_d = 2 · m_current_body / h² / number_of_points
```

При решении A используется масса A, при решении B — масса B. Это не один общий коэффициент ограничения: обе стороны вносят силы разного масштаба. Такой путь добавлен поверх основной AVBD-схемы.

**Скалярное сведение текущего кода:** два динамических шара радиуса 0.5, центры `A=(1.01,0,0)`, `B=(0,0,0)`, массы 1 и 100 кг, скорости −1 и 0 м/с; гравитация и вращение нулевые, `h=1/60`. Зазор 0.01 попадает в speculative band; прогнозируется сближение, а TOI-порог не достигается. Одна точка контакта, плечи коллинеарны нормали — вращательные строки не участвуют.

После сокращения массы уравнения предела локальных итераций имеют вид:

```text
3·dA − 2·dB = yA
−2·dA + 3·dB = yB
```

Результат перестаёт зависеть от масс. Модель даёт:

| Величина | До шага | После 10 итераций | Предел итераций |
|---|---:|---:|---:|
| Скорость A, м/с | −1 | −0.600120 | −0.6 |
| Скорость B, м/с | 0 | −0.400180 | −0.4 |
| Суммарный импульс, кг·м/с | −1 | −40.618164 | −40.6 |
| Кинетическая энергия, Дж | 0.5 | 8.187291 | 8.18 |

Это **результат исполняемой скалярной модели участка**, не лог запущенного Ornis. Он показывает структурную проблему: ошибка сохраняется при сходимости, а не объясняется ограничением в 10 итераций. Контроль с одним общим penalty пары сохраняет импульс −1.

**Исправление:** определять параметры и силу ограничения на пару/строку, общие для обоих тел; массы должны входить в инерционные блоки и, при необходимости, в общую эффективную массу пары. Закрепить black-box тестами смешанных масс, суммарного импульса и отсутствия генерации энергии без внешней работы.

### A3 · P2 — При скольжении не сохраняется ограниченная сила трения в `λ`

**Код:** `avbd.rs:2606–2624`.

Ornis присваивает `pt.lam[1/2] = f[1/2]` только при `s_ell <= 1`. То есть за пределами friction cone остаётся старый тангенциальный `λ`.

В авторском `manifold.cpp:148–173` разделены две операции:

1. Вычислить `F=K·C+λ`, ограничить силу и **сохранить полученный F в λ**.
2. Увеличить penalty тангенциальных строк **только если не требовалось ограничение**. [3](https://github.com/savant117/avbd-demo3d)

В Ornis условие второй операции ошибочно распространяется и на первую.

**Контрпример:** `K=(100,100,100)`, `C=(-0.01,0.1,0)`, старый `λ=(-9,4,0)`, `μ=0.5`. Нормальная сила −10, сырая тангенциальная сила 14, граница 5:

```text
Эталон: λ_new = (-10, 5, 0), tangent penalty не растёт.
Ornis:  λ_new = (-10, 4, 0), сохраняется старый tangent λ.
```

Результат эталона подтверждён прямым вызовом скомпилированного `Manifold::updateDual`. Отличие Ornis подтверждено чтением условия и его скалярным воспроизведением.

**Последствие:** dual-состояние не соответствует ограниченной силе, использованной primal-проходом; ошибочная история при переходах slide↔stick. Это не доказательство конкретной величины дрейфа сцены — её нужно измерить отдельно.

**Исправление:** разнести commit projected force и gate для penalty growth; отдельно определить политику обнуления/сохранения состояния при размыкании контакта.

### A4 · P1 — `C≈0` ошибочно трактуется как отсутствие реакции ограничения

**Код:** `avbd.rs:151–156`, `1815–1820`, `1899–1909`; аналогичные guards есть у других joints.

Primal-проход пропускает всю строку при `abs(C)<1e-7`. Но в augmented-Lagrangian формулировке при `C=0` может оставаться ненулевая реакция `F=λ`. Именно множитель позволяет hard constraint держать нагрузку без обязательной деформации. [8](https://graphics.cs.utah.edu/research/projects/avbd/Augmented_VBD-SIGGRAPH25.pdf)

**Минимальный пример:** `C=0`, `λ=-10`, `K=100`, `J=1`:

```text
Эталонный вклад в gradient = -10, в Hessian = 100.
Ornis пропускает строку: оба вклада равны 0.
```

Эталонный результат проверен непосредственным вызовом C++ `updatePrimal`.

Это не обычный harmless epsilon для прекращения роста penalty. Из локальной системы исчезает уже существующая сила, даже если `λ` велик.

**Исправление:** не выключать активное ограничение только по малой геометрической невязке. Подавление численного шума в ramp/update рассматривать отдельно от сборки `JᵀF` и `JᵀKJ`. Проверить нагруженное равновесие и малые возмущения вокруг него.

### A5 · P2 — Prismatic limit теряет augmented-член в dual-update

**Код:** primal `avbd.rs:2323–2326`; dual `2846–2866`.

Primal вычисляет:

```text
F = clamp(K·C + lim_dual)
```

а dual сохраняет:

```text
lim_dual = clamp(K·C)
```

Комментарий объясняет это тем, что «lambda = F» означает присваивание, а не накопление. Однако в AVBD **сам F уже содержит старую λ**: присваивание `λ_new=F` эквивалентно `λ_old+K·C` до ограничения. Это видно и в Algorithm 1, и в `joint.cpp:130–139` авторского демо. [8](https://graphics.cs.utah.edu/research/projects/avbd/Augmented_VBD-SIGGRAPH25.pdf) [3](https://github.com/savant117/avbd-demo3d)

**Контрпример нижнего лимита:** `C=-0.01`, `K=1000`, `λ_old=-50`. Primal и AVBD dual дают −60, текущий Ornis dual — −10 даже при неизменившейся между вызовами конфигурации.

Таким образом, эта конкретная строка — изменённая penalty/servo-схема, а не заявленный augmented update. Для скалярной удерживающей строки в пределе `lim_dual=K·C`, поэтому сила становится `2K·C`; при конечном K нагрузке нужна ненулевая ошибка. Сам по себе cap penalty не является нарушением AVBD — проблема в выбрасывании λ.

**Исправление:** восстановить согласованный primal/dual-контракт и исследовать исходную нестабильность отдельно либо честно выделить этот путь как другой тип ограничения с ограниченной жёсткостью. Не маркировать текущую формулу как точный порт AVBD.

### A6 · P2 — Нулевой коэффициент трения по одной оси обнуляет обе оси

**Код:** `avbd.rs:1668–1675`.

Если `b1=0`, но `b2>0`, устанавливается `s=∞`, затем общий `k=0`. Поэтому исчезает и разрешённая вторая компонента.

**Пример:** `Fn=-10`, `μ=(0,0.5)`, сырая тангенциальная сила `(0,10)`. Допустимый ограниченный результат `(0,5)`, функция возвращает `(0,0)`.

Это дефект расширения с анизотропным трением, не признак неправильной идентификации AVBD. Нулевые коэффициенты допустимы по контракту `RigidBody` (`body.rs:75–85`).

**Исправление:** отдельно обработать вырожденный эллипс — отрезок или точку. Добавить случаи `(0,μ)`, `(μ,0)`, `(0,0)`.

## 3. Что является упрощением, а не доказательством ошибки

- **Последовательный primal.** Допустим для CPU-реализации AVBD; в авторском демо тоже обычный проход. GPU/coloring — способ исполнения, не определение метода. [3](https://github.com/savant117/avbd-demo3d)
- **Параметры `α=0.99`, `γ=0.999`, `βlin=10000`, `βang=100`.** Они совпадают с выбранной версией авторского `solver.cpp:109–131`. Отличие от констант публикации не следует объявлять багом. [3](https://github.com/savant117/avbd-demo3d)
- **Exp/log для quaternion вместо chord-операторов.** Это изменение дискретизации, а не автоматически неверный алгоритм. Но «exact port» к нему неприменимо; большие углы и согласованность производных требуют своих тестов. Код: `avbd.rs:325–370`; опубликованные операторы: §4, equations 20–21. [8](https://graphics.cs.utah.edu/research/projects/avbd/Augmented_VBD-SIGGRAPH25.pdf)
- **Начальная поза всегда равна inertial target.** В Ornis `1011–1018` отсутствует adaptive initial guess авторского `solver.cpp:173–185`. Это в первую очередь различие сходимости при малом числе итераций, а не основание переименовать метод. [3](https://github.com/savant117/avbd-demo3d)
- **Неполный охват soft/finite-stiffness forces.** Например, wheel spring в `avbd.rs:2063–2077` сразу использует вычисленную физическую жёсткость. На основании такого кода нельзя заявлять воспроизведение всего набора задач с высокими stiffness ratios из статьи; ограниченный rigid-body AVBD остаётся AVBD.

## 4. Тесты и масштабирование: что они подтверждают

### Имеющиеся тесты полезны, но не являются сравнением с эталоном

- Стек после 300 шагов, допустимые высоты/дрейф/скорости: `tests/avbd_engine.rs:31–60`.
- Ball joint: допускается 15 см ошибки якоря: `tests/avbd_engine.rs:101–134`.
- Canonical snapshot закрепляет текущее поведение: `tests/avbd_engine.rs:1410–1421`. Сам по себе он не отличает правильную физику от детерминированной ошибки.
- `avbd_confluence_one_vs_many_threads` прямо говорит, что проверяет **parallel discovery**, а solver sweep остаётся последовательным: `tests/avbd_engine.rs:1439–1446`. Называть это проверкой параллельного primal/dual-солвера нельзя.
- Проверки изолированных `row_c`, projected-lambda, равновесия при `C=0, λ≠0` и указанных смешанных масс в просмотренных AVBD-тестах не обнаружены.

Часть settle-проверок оценивает состояние уже после включения sleep. Дополнительные измерения без усыпления нужны, чтобы отделить математическую устойчивость от замораживания тел.

### Масштабирование пока не повторяет GPU-реализацию публикации

`generate_pairs` перебирает все пары (`avbd.rs:1462–1484`); распараллелен именно discovery. В каждом `solve_body` перебираются все контактные пары и joints с последующей фильтрацией (`1737–1744`, `1868–1874`), вместо обхода только инцидентных ограничений. Это даёт как минимум существенные `O(N²)` и `O(N·(contacts+joints))` участки за sweep; дополнительные линейные поиски пар могут повышать стоимость.

Следовательно, результаты масштабирования из статьи к текущему Ornis неприменимы без отдельного benchmark и иной организации данных/исполнения. Это граница готовности, а не доказательство подмены AVBD.
