# Стратегический поворот: от нативного UI к браузерному редактору

> Дата принятия решения: 24 июля 2026 г.
> Статус: активно

## Контекст

После нескольких месяцев разработки собственного UI-движка (`crates/ui`) стало очевидно, что поддержка полноценного HTML/CSS/JS-рендерера внутри игрового движка — задача, требующая ресурсов целой команды браузерной разработки. Бесконечные баги layout, рендеринга, JS-интерпретации и IPC отвлекают от развития ядра движка.

## Решение

**Приостановить активную разработку нативного UI-крейта и перейти на браузерный редактор.**

### Что это значит

| Было | Стало |
|------|-------|
| Редактор — Vello overlay внутри winit-окна | Редактор — веб-приложение в браузере |
| Сцена рендерится в нативное окно через wgpu | Сцена рендерится в `<canvas>` браузера через WebGPU (WASM) |
| UI-крейт (`crates/ui`) — активная разработка | UI-крейт остаётся в репозитории, но заморожен |
| JS через `boa_engine` внутри Rust-процесса | JS исполняется нативно в браузере |

### Почему это разумно

1. **Фронтендеры пишут на привычном стеке**. React/Vue/Svelte + обычный CSS. Никаких ограничений Boa или кастомного layout.
2. **Браузер уже решил проблемы рендеринга**. 60+ лет инженерии в Chrome/Firefox/Safari — нам не перещеголять это своими силами.
3. **Фокус на ядре**. ECS, GPU-диспетчер, физика, аудио — вот где конкурентное преимущество. UI — коммодитизированная область.
4. **Blitz и Boa ещё не зрелые**. Когда `blitz` (Dioxus-рендерер) и `boa_engine` (JS в Rust) достигнут зрелости — можно будет вернуться к нативному UI. Пока нет смысла тянуть груз самим.

### Архитектура переходного периода

```
┌─────────────────────────────────────────┐
│           Браузер (Chrome/Firefox)       │

│  │   Editor UI  │    │  Game Canvas │   │
│  │  (React/Vue) │    │ (WebGPU/WASM)│   │
│  └──────┬───────┘    └──────┬───────┘   │
│         │                   │           │
│         └───────┬───────────┘           │
│                 │ WebSocket/HTTP        │
└─────────────────┼───────────────────────┘
                  │
┌─────────────────┼───────────────────────┐
│  Ornis Engine (Rust, фоновый процесс)   │
│  ┌──────────────┐    ┌──────────────┐   │
│  │   ECS Core   │    │  HTTP Server │   │
│  │ Sparse Sets  │◄──►│  (port 3420) │   │
│  │  GPU Dispatcher                     │
│  └──────────────┘    └──────────────┘   │
│                                          │
```

### План миграции

1. **Сейчас**: `cargo run --features editor-only` запускает только HTTP-сервер редактора (порт 3420). Нативное winit-окно не создаётся.
2. **Ближайшее время**: Редактор в браузере коммуницирует с движком через REST API / WebSocket. Сцена рендерится в браузерный canvas через WASM + WebGPU.
3. **Когда blitz/boa созреют**: Возможен возврат к нативному UI как опция. Код в `crates/ui` остаётся для этого.

### Что заморожено

- Дальнейшая разработка `crates/ui` (headless DOM, Vello-рендеринг, JS-bridge)
- Интеграция Servo
- Нативный In-Game Editor (Vello overlay)
- Расширение MaterialX / OpenPBR в UI-контексте

### Что продолжаем развивать

- **Ядро ECS** (`crates/core`) — Sparse Sets, SmartStore, физика
- **Рендер** (`crates/render`) — OpenPBR, WGSL-шейдеры, WebGPU-backend
- **Аудио** (`crates/audio`)
- **Макросы** (`crates/macros`) — smart_pipeline, gpu_pipeline
- **WASM-target** — компиляция движка в wasm32-unknown-unknown

### Риски

| Риск | Митигация |
|------|-----------|
| Браузерный редактор требует постоянного соединения | Локальный HTTP/WebSocket сервер, fallback на статичную страницу |
| WebGPU не везде доступен | Fallback на WebGL2 через wgpu; статус WebGPU растёт |
| Производительность WASM vs нативный | Критичные системы (физика, рендер) остаются на Rust; JS только UI |
| Потеря инвестиций в UI-крейт | Код не удаляется, а архивируется. При зрелости blitz — большая часть логики переиспользуется |

### Критерий возврата к нативному UI

- `blitz` достигает стабильного релиза с поддержкой CSS-фреймворков
- `boa_engine` проходит >90% тестовuite ECMAScript
- Появляется выделенный разработчик/команда для UI-слоя
