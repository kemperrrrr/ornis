# 001: AVBD CPU-спайк на стеке (M0)

## Вопрос

Given сцена «пол + 4 бокса» (как `four_box_stack_stays_stable`, зазоры 2см),
when шаг считается упрощённым rigid-AVBD из официального демо (per-body 6×6
LDL, primal/dual, 10 итераций, dt=1/60), then стек стоит 5с в тех же гейтах,
что SI (высота ±0.1, дрейф <0.15, скорости <0.08) — и видно, сколько итераций
нужно до покоя против SI.

## Подход

Порт ядра `Solver::step()` + `Manifold::updatePrimal/updateDual` из
`savant117/avbd-demo3d` (MIT) на наши типы. Упрощения: выровненные боксы,
угол-малые ротации, контакты «4 угла ↔ опора», общий тангенциальный penalty,
без реституции. В том же бинаре рядом едет SI на той же сцене.

## Запуск

```bash
cargo run -p ornis-physics --release --example avbd_spike
```

## Код

`../../crates/physics/examples/avbd_spike.rs` — THROWAWAY, удалить после M1
(рядом с `probe_100k.rs`, держится отдельно от lib).

## Verdict: VALIDATED

### What worked
- Стек 4 боксов стоит 300 шагов: высоты ±6мм (у SI ±25мм), дрейф 0,
  скорости <0.008. Покой — на **11-м шаге** (наш SI-гейт: 300 шагов).
- Формулировка один в один с официальной (Taylor `C = C0*(1-alpha) + J*dq`,
  аддитивный рампинг `penalty += beta*|C|`, `lambda = F`, Eq.19) — проверена
  чтением `solver.cpp`/`manifold.cpp`/`maths.h` (row-major 6×6 LDL совпал).

### What didn't (и что это стоило)
- Первая версия с угаданными dual-правилами (live gap, рампинг ×2,
  инкрементальная lambda) — coupling-неустойчивость, взрыв/провал. Вывод:
  дьявол в `updatePrimal/updateDual`, угадывать нельзя — только порт.
- Порядок sweep (снизу вверх vs сверху вниз) — не влияет (проверено тогглом).

### Surprises
- **Корневой баг спайка: якорь нижней стороны.** Пересчёт `rB` из живых
  позиций подмешивал движение верхнего тела в нижний якобиан и качал
  энергию при быстром относительном движении. Фикс — материальный якорь,
  зафиксированный на генерации (как `rB` в `collide()`). После фикса —
  с первого прогона PASS, включая дроп-транзиент 2см.
- Stale lambda (−30) + рампинг в разделении = runaway-запуск (бокс улетел
  на y=440). Было следствием якоря, не формулировки; после фикса не
  воспроизводится. Для M1 держать в уме как известный режим.

### Recommendation for the real build
- M0 закрыт → M1 (`AvbdEngine: PhysicsEngine`) разблокирован.
- Контакты обязаны нести материальные якоря обеих сторон с момента
  детекции (урок для будущей narrowphase→AVBD стыковки).
- DSL-цена подтверждена низкая: нужен `float3x3` + локальный scratch +
  helper-inclusion (LDL 6×6 общий для CPU/GPU) — никаких 12×12.
