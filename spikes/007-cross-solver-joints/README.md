# 007: cross-solver joints (DESIGN SPIKE)

> Дизайн-спайк: только документ, прод-кода нет. Правило: `crates/*/src` не трогать.

## Вопрос

Given роутинг M3 по островам (контактная компонента всегда шагает в
одном солвере), when джойнт соединяет тела, оказавшиеся в РАЗНЫХ
солверах, then какой coupling честен (без зеркального бульдозера из
001) — фиксируем варианты, рекомендацию и гейт.

## Контекст: статус-кво и почему вопрос открыт

- M3 v1 — вне скоупа: cross-solver joints не нужны как класс
  (PLAN.md:710-717). Механика: `SplitState::route`
  (`crates/physics/src/split.rs`) линкует концы каждого джойнта в один
  union-find остров (gear — все четыре стороны), а `rebuild` создаёт
  локальный джойнт в солвере только если оба конца локально там. Итог:
  концы всегда в одном солвере, cross-joint rows не существует.
- Гистерезис тот же, что в спайках 002–004: `SLEEP_SPEED=0.2`,
  `WAKE_SPEED=0.5`, `QUIET_STEPS=30`, связь островов через swept AABB +
  `LINK_MARGIN=0.05` (`swept_bounds`). Покой инвариантен к начальному
  роутингу (004); миграций ~2 на цикл wake+sleep без треша (003).
- Спайк 001 (`spikes/001-cross-solver-contact`): staggered
  kinematic-зеркала (чужое тело как kinematic с лагом в шаг) бульдозят —
  телепортированное зеркало перекрывает соседа, SAT резолвит глубокое
  перекрытие вбок: тихий side-eject (z≈3–7, скорости ~0 — тихий неверный
  ответ). Односторонний coupling без переноса веса тоже не работает:
  низ не чувствует верха (неверно для тяжёлого верха и цепочек трения).
  Проверка поз покоя обязательна, скоростей недостаточно.

## Варианты

### (a) Принудительная колокация — статус-кво + явный API-err

Джойнт пинит остров (как сейчас): концы всегда мигрируют вместе,
разрезать остров по джойнту запрещено. Попытка вручную растащить концы
по разным солверам — явная ошибка API (возврат `None`/err на уровне
`Engine`, а не молчаливое неверное поведение). Cross-joint rows не
нужны вообще.

- За: ноль новой математики; наследует все гарантии 002–004
  (rebuild + zombie-guard `restore_mass`, bounded-миграции,
  routing-invariant rest); joint rest-reference (`JointSnapshot`) живёт
  в глобальном реестре и переживает rebuild.
- Против: длинная цепь/маятник тащит весь остров в один солвер
  (острова жиреют); нет «половина цепи в AVBD, половина в Builtin».

### (b) Schwarz alternating с переносом веса — запрещён итогом 001

По очереди шагать остров A с замороженным якорем B, потом наоборот,
с переносом реакции (force-level exchange Genesis-Legacy-style).
Это реинкарнация staggered-зеркал: пока A шагает, якорь B stale на шаг;
при подходе тел телепорт перекрывает соседа и SAT уводит вбок — тот же
side-eject из 001, только теперь через джойнт-якорь, а не контакт.
Односторонний вариант (без переноса веса) 001 уже забраковал отдельно.
Вариант фиксируем как отвергнутый, не как «попробовать позже».

### (c) Виртуальный coupling-row в обоих солверах с делением жёсткости

Джойнт-ряд собирается в ОБОИХ солверах одновременно, каждый со своей
половиной жёсткости (или penalty сплитуется по массам), концы остаются
каждый в своём солвере, связь — через согласованный compliance.
Честный bidirectional coupling без телепортов.

- За: единственный вариант, сохраняющий разрез; без stale-якорей —
  оба конца живые в своих солверах.
- Против: новая математика в обоих солверах (AVBD primal + builtin
  velocity/position — деление жёсткости формулируется дважды, dual-память
  AVBD удваивается); риск расщепления rest-reference при rebuild;
  сходимость связки «солвер+половинная жёсткость» не измерена —
  нужен отдельный спайк с throwaway-кодом, а не дизайн-док.

## Рекомендация

Держать (a) ещё на один цикл: колокация + явный API-err при попытке
разрезать. (b) запрещён итогом 001. (c) — честный, но тянет на
отдельный кодовый спайк (не дизайн-док) с измерением сходимости;
до него руки дойдут только если острова реально зажиреют на цепях.

## Гейт спайка (когда дойдёт до кода)

Двухмаятниковый тест через границу солверов: два звена Ball-цепи,
которым роутер назначил бы разные солверы, качаются N шагов без
side-eject и держат якорь в поведенческом допуске (по образцу
`ball_joint_pendulum_holds_anchor` / `ball_joint_chain_hangs`).
Ассёртить ПОЗЫ покоя/амплитуды, никогда одни скорости (урок 001:
тихий side-eject выглядит как покой). Для варианта (a) гейт
вырождается в проверку: цепь не разрезается + запрещённый разрез
возвращает явную ошибку.
